# Process-wide `hasFallbackSubs` flag makes every no-subscriber write pay the WeakMap lookup once any non-extensible target is observed

**Category:** enhancement
**Status:** ready-for-human
**Change:** commit e8c7630 (2026-10-19, local trunk only, never pushed), reworked as commit 6008106 on branch `fix/sealed-writes-notify` in draft PR #178 because the placeholder failed the 1% gate against origin/trunk; see the second outcome note

The fix for sealed-object writes (branch `fix/sealed-writes-notify`, commit `63eb432`, issue `2026-10-18-sealed-writes-skip-subscribers.md`) gates the `proxyCacheSubs` WeakMap lookup in the hookless set handler and the batch fast path behind a module-level boolean `hasFallbackSubs`. `storeSubscriberSet` sets it the first time a subscriber set goes to the WeakMap instead of the `SUBSCRIBERS` symbol, which happens for any non-extensible target and for a Proxy target whose `defineProperty` trap rejects symbol keys. The flag never resets. From that moment on, every hookless write to a target that carries no `SUBSCRIBERS` symbol (an ordinary extensible object nobody has subscribed to yet) performs a WeakMap `get` that misses. The agent's attempt (a), which did the lookup unconditionally, measured that cost at about +4 ms per million writes on the "state no subs" benchmark (36.84 ms baseline, 41.05 ms with the lookup, +11%). The benchmark suite never exercises a non-extensible target, so it cannot see this regression. The code carries a `ponytail:` comment at the flag declaration naming "per-target marking" as the upgrade path. The maintainer decided on 2026-10-19 to work on this next.

Candidate designs, with what is known about each. None has been benchmarked yet.

1. Keep the flag. Zero cost until the first non-extensible subscription; after that, the +11% on no-subscriber writes for the rest of the process. The fix for post-creation sealing (`Object.seal(raw)` after `state(raw)`) is covered because the flag is set at subscription time, not creation time.
2. Replace the flag with `Object.isExtensible(rawTarget)` when the symbol is absent. Always pays one intrinsic call on the no-subscriber path, probably cheaper than a WeakMap miss but unmeasured. Misses the Proxy-target `catch` case, where `isExtensible` is true yet the set lives in the WeakMap; that case would need the flag or be declared unsupported.
3. Pick the handler at `state()` time: a second prebuilt hookless handler whose set trap and batch path consult the WeakMap, chosen when `defineProxyProperties` fails to define the `PROXY` symbol (it already detects that and falls back). Zero cost on extensible targets. Fails for targets sealed after `state()` but before their first subscription, since the symbol is only defined lazily by `getSubscribers`. Would need the flag as a backstop or a `preventExtensions` trap that swaps behavior.
4. Define the `SUBSCRIBERS` slot eagerly in `definePropertyOnTarget` with a writable placeholder so that "symbol absent" means "fallback target" exactly, for both pre- and post-creation sealing. Costs one extra `defineProperty` per `state()` call; the "state creation" benchmark (100,000 `state({ v })` calls, 24.27 ms baseline) will show it. Frozen-after-creation targets would then have a non-writable placeholder, and `getSubscribers` would need to fall back to the WeakMap when the assignment fails.

Decision needed: which cost is acceptable, and whether the Proxy-target `catch` case and post-creation sealing are supported scenarios. The answer should be recorded in `src/AGENTS.md` next to the handler description so a future audit does not re-flag it.

## Triage notes

**Decision (maintainer, 2026-10-19):** benchmark first, then design 2 (`Object.isExtensible`). Two benchmark rows were added to the suite before any change: "sealed write 1 sub" and "state no subs after seal". With them, trunk `63eb432` measured "state no subs" at 41.13 and 41.26 ms (10 cycles, two runs) against 37.2 to 37.5 ms in earlier runs without a sealed target in the process, which confirmed the ceiling at about +10.5%.

**Design 2 rejected by measurement.** The full suite drifted too much between runs on this machine to resolve it (two trunk runs of identical code summed 871 and 956 ms), so a micro-benchmark was used: 15 reps of the 1,000,000-write "state no subs" loop per process, four builds interleaved in a fixed order, three rounds. Medians: trunk with no sealed target seen 25.5 to 26.9 ms; trunk after a sealed subscription 30.2 to 30.8 ms; design 2, with or without a sealed subscription, 30.8 to 32.0 ms. The `Object.isExtensible` call costs at least as much per write as the WeakMap miss it replaces, and it is paid on every write instead of only after arming.

**Design 4 implemented instead** (the eager placeholder): `definePropertyOnTarget` defines `SUBSCRIBERS` as a writable `null` on every extensible target at `state()` time. The hookless set handler and the batch fast path treat `undefined` as "set lives in `proxyCacheSubs`" and `null` as "no subscribers". `storeSubscriberSet` assigns into the slot when it is `null`, which works on a target sealed after `state()` because sealing keeps writability; a target frozen after `state()` makes the assignment throw, and the catch stores in the WeakMap. The flag is gone. Same micro-benchmark, three rounds: design 4 25.6 to 26.5 ms with or without a sealed subscription, against trunk 25.6 to 25.9 ms unarmed. Verify passed, 258 of 258 tests. Full-suite A/B and branch coverage pending at the time of this note.

**Outcome (2026-10-19, later the same day):** the maintainer chose design 2 first, design 4 was built only after design 2 failed the measurement, and the maintainer then accepted design 4 with the creation cost below and committed it on trunk as `e8c7630`, keeping the two benchmark rows and the new test. Full suite, two interleaved trunk-versus-design-4 pairs at 10 cycles, sum of the 18 medians: 866.94 versus 864.48 ms and 925.17 versus 885.37 ms, both within the 1% aggregate gate. "State no subs" fell from 42.2 and 43.9 ms to 36.8 and 36.6 ms, and "state no subs after seal" from 42.7 and 43.5 to 37.3 and 35.9 ms, so the ceiling is gone in the suite as well. The cost moved to "state creation": 27.1 and 27.6 ms on trunk against 36.9 and 36.2 ms with the placeholder define. A creation micro-benchmark (15 reps of 100,000 `state({ v })` calls) shows the cost depends on heap state: with a forced GC before each rep the medians are 23.2 to 29.0 ms on trunk against 24.5 to 28.0 ms with the placeholder, about +1 to +3 ms; without the forced GC they are 25.9 to 28.9 ms against 41.0 to 42.6 ms, +14 to +15 ms, which is the realistic condition and brackets the suite's +9 ms. Retained heap per `state()` is identical in both builds (155.4 bytes per object over 100,000 retained proxies), so the cost is not larger objects; it is garbage-collection or allocation work that the extra define provokes, and the V8 mechanism behind it was not identified. In per-call terms the placeholder adds roughly 90 to 150 ns to a `state()` call that costs roughly 270 ns on trunk. Two cheaper spellings of the define were measured and rejected: a hoisted shared descriptor object was slower in the GC-isolated micro-benchmark (30 to 37 ms minima), and a single `Object.defineProperties` call for both symbols was far slower (46 to 52 ms minima). Branch coverage: the only branch the change left uncovered was the `catch` in `storeSubscriberSet`, which a new test (freeze the raw object after `state()`, then subscribe) now covers; the core file reports the same 23 pre-existing uncovered branch entries as trunk `63eb432`, no more. Verify passed with 259 of 259 tests.

**Second outcome (2026-10-19, PR preparation):** when the whole branch was measured against origin/trunk rather than against the previous local commit, design 4 failed the gate: two interleaved base-versus-branch pairs at 10 cycles summed 838.44 versus 850.51 ms and 838.58 versus 860.05 ms (+1.4% and +2.6%), with "state creation" at +10 ms per 100,000 calls in both pairs. A creation micro-benchmark of four define spellings (hoisted descriptor, `Reflect.defineProperty`, defining `SUBSCRIBERS` before `PROXY`, plain assignment) showed that no `defineProperty` form avoids the cost under realistic heap conditions (39 to 42 ms against 25 to 26 ms for base without a forced GC; all within 2 ms of base with a forced GC before each rep), and only plain assignment matched base, which is unusable because an enumerable symbol would be copied by spread and `Object.assign`. The placeholder was therefore removed. The replacement distinguishes fallback targets by the `PROXY` symbol, which `state()` already defines on every extensible target: a target without `PROXY` never took symbols, so the hookless set handler and the batch fast path consult `proxyCacheSubs` for it without any flag. The process-wide flag returns, but `storeSubscriberSet` arms it only when a target that carries `PROXY` lands in the WeakMap, which happens only for a target sealed or frozen after `state()` and before its first subscription. A test for that case (seal after `state()`, subscribe, direct and batched writes) was added; it fails on origin/trunk and passes on the branch. The benchmark for this version was running when this note was written; the PR description carries the final numbers.
