# Shared load sites in subscriber scheduling deoptimize on mixed array and object writes

**Status:** needs-triage

The ticket 04 investigation of change `wrap-fill-and-copywithin` (second implementer, 2026-10-25, report section 15) found that `scheduleSubscribersForTarget` and `findSubscribers` in `src/index.ts` serve array and plain-object targets from the same load sites, and that a benchmark sequence mixing array and object writes (`state write 1 sub`, push/pop, `fill`, `many dependencies`) makes V8 bail out of them 14 and 3 to 6 times per run on every commit measured, including the pre-change baseline `87c8823`. It is the same class of pollution that commit `b595300` removed from `handleBatchFastPath` by giving arrays their own set handler and batch write path, where it cost `many dependencies` about 10% on the median after `fill` moved onto the batch path. This one is not a regression from the change and was left alone. Candidate for the library-wide performance tournament (`2026-10-23-library-wide-performance-tournament.md`): measure a split of those two functions by target kind with the same interleaved protocol, or confirm the bailouts cost nothing measurable.
