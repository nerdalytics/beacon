# Drop the unread `HOOKS` slot write on hooked objects and the `frozenHooksCache`

**Status:** ready-for-agent

**Change:** drop-unread-hooks-slot-on-objects

The maintainer ruled Q80 a on 2026-10-25: remove the dead work, close `HOOKS_TODO.md` item C1 with it. Facts at commit 18931ce in `src/index.ts`. `hooksSlotFor` returns the hooks object unchanged for a non-array target and a `DirectArrayContext` for an array. `definePropertyOnTarget` defines the `HOOKS` symbol on every extensible target whose slot is truthy, so each `state(obj, hooks)` call and each nested object wrapped through `wrapNestedObject` pays one `Object.defineProperty` that nothing reads: the only reads of `[HOOKS]` are `directPushWrapper` and `directPopWrapper`, and both act only on a `DirectArrayContext`. A hookless object passes `undefined` and skips the write. `storeHooksForFrozenTarget` writes hooked non-extensible targets into `frozenHooksCache`, which has one declaration and one `set` and no `get` anywhere in the file, so it is dead for objects and arrays alike. The hooks keep firing through the handler closures, as C1 already states. A micro probe of the two `defineProperty` calls on 500,000 fresh objects measured 102 ns per object for the `PROXY` symbol alone and 179 to 202 ns with the `HOOKS` symbol added; `scripts/benchmark.ts` has no hooked creation case (its three creation cases are hookless), so the suite does not show it.

Smallest change: `hooksSlotFor` returns `undefined` for a non-array target; delete `storeHooksForFrozenTarget` and `frozenHooksCache`; `HooksSlot` narrows to `DirectArrayContext | undefined`; the `defineProxyProperties` catch and non-extensible branches keep returning `false` so the `proxyCache` entry still happens. Update the header comment in `tests/property-frozen-sealed.test.ts` that names `frozenHooksCache`, the `definePropertyOnTarget` row in `src/AGENTS.md`, and mark C1 shipped in `HOOKS_TODO.md`. No consumer-visible behavior changes: the symbol is module-private, so this is `perf(state)`, not breaking. Gate: the usual 1% per benchmark case against the base commit; add a hooked `state creation` case with a trunk number first (Q66 d) so the win is visible.
