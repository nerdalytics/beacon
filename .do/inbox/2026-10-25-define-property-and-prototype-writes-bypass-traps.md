# `Object.defineProperty` and prototype writes bypass the traps

**Status:** needs-triage

The Proxy handler in `src/index.ts` at commit 18931ce defines `deleteProperty`, `get`, `has`, `ownKeys` and `set`. It has no `defineProperty`, `setPrototypeOf`, `getOwnPropertyDescriptor`, `getPrototypeOf` or `preventExtensions` trap, so those operations forward to the raw target without tracking, notification or hooks. A probe on 2026-10-25 (`probe-object.mjs`, session scratchpad) with an effect reading `$o.a` and an `onWrite` hook: `Object.defineProperty($o, 'a', { value: 2 })`, `Object.defineProperties` and `Reflect.defineProperty` change the raw value, wake nobody and call no hook; `Object.defineProperty($a, 'length', { value: 0 })` empties a reactive array the same silent way, while `$a.length = 0` notifies. `Object.setPrototypeOf($o, proto)` changes the prototype silently; `$o.__proto__ = proto` goes through the set trap, which assigns `rawTarget['__proto__']` and so does change the prototype, calls `onWrite` with property `__proto__`, and wakes only subscribers of `__proto__`, never the readers of an inherited property. Reads through `Object.getOwnPropertyDescriptor` and `Object.getPrototypeOf` are not tracked; `in`, `Object.keys` and `JSON.stringify` are. `Object.assign`, `Reflect.set` and `delete` behave like direct writes. `Object.freeze` and `Object.seal` forward silently and a later write throws `TypeError` from the strict-mode raw write, which the frozen and sealed tests already cover. Decide which of these count as supported write paths: a `defineProperty` trap that runs the set-trap bookkeeping would close the main gap; the prototype paths may be better documented as unsupported. No documentation names any of them (`grep` over `README.md`, `AGENTS.md`, `src/AGENTS.md` and the v2002.0.0 handbook tree).

**Follow-up:** step 3 of 3 in the object-side chain proposed on 2026-10-25. Order: (1) `2026-10-25-drop-unread-hooks-slot-on-objects.md`, (2) `2026-10-25-fill-and-copywithin-not-batched.md`, (3) this note. Last because it needs a design decision before code: which `Object.*` paths Beacon supports (a `defineProperty` trap that runs the set-trap bookkeeping is the candidate), and whether `setPrototypeOf` and `__proto__` are documented as unsupported or intercepted. It also needs its own capability spec, since `array-mutation` covers the seven methods only; a new `object-mutation` capability under `openspec/specs/` would hold the trap contract for both kinds of target. Depends on step 1 for the hooked `state creation` benchmark case and trunk number, because the trap is added to the two handler objects in `src/index.ts`, `HOOKLESS_HANDLER` and the hooked one built in `state()`. New notifications and hook calls where there were none is a consumer-visible change, so it ships in the breaking release with PR 186 and step 2. The equal-value question in `2026-10-22-equal-value-write-in-sync-effect-raises-loop-error.md` should be settled in the same release, because the new trap would copy whichever order of loop check and equality check `performWrite` has at that time.
