# 07: Direct fast path for push and pop

**Area:** state

**Blocked by:** 06

**What to build:** `push` and `pop` on a reactive array run the native method on the raw target and then do, by hand, exactly the bookkeeping the get, set and delete traps would have done, with the same arguments a direct property access produces. The reference is what a plain Proxy reports for the same call: `push` reads `push` and `length`, then writes each new index and `length`; `pop` reads `pop`, `length` and the last index, then deletes the last index and writes `length`. So the direct path calls `onRead` for the method name and each property read, `onWrite` with the infinite-loop check for each property the set trap would have written, `onDelete` for the index `pop` removes, which gets no loop check and no equal check because the delete trap has none (Q57 a), and it keeps an equal value silent. Outside an effect it wakes each subscriber of the array once per call, deferred to the outermost batch when called inside one; inside a child or microtask effect it schedules per property exactly as the set trap's effect path does today, so the direct path changes no observable behavior (Q58 a). The other five mutating methods keep the Proxy receiver of ticket 03. The maintainer's performance rule is per benchmark case: Beacon must be faster over time, never slower, and 1% is treated as noise. Measurement is interleaved to beat machine drift: three full `npm run benchmark` runs of the base commit (the change branch's tip before this ticket) alternating with three full runs of the final commit, in one session on one machine, with the median of each case's `med=` and `total=` fields compared across the three runs of each side. All six outputs go into the ticket report. The gate for the hookless array case is trunk's own number from ticket 01, because trunk ran the same trap work there. The gate for the hooked array case is the same trunk hookless number (Q54 a), because trunk's 17.34ms for the hooked case measured a wrapper that called no hook and tracked nothing. No version bump, no handbook change.
