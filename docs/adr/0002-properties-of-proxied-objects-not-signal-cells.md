# Reactivity is per property of a Proxy-wrapped object, not per signal cell

Through v1000 Beacon followed the TC39 signals proposal's shape: a state was a cell with `get()`, `set()` and `update()`, and `lens()` was the opt-in for being notified about one part of a value. Writing through `update()` was awkward, worst for n plus 1 style changes, and per-part notification was something users had to ask for. In epoch 2 (commit 2f3a46f, tag 2000.0.0, 2026-04-11) we decided that `state()` wraps a plain object in a Proxy, writes are plain assignments, and dependency tracking is per property for every read, so `lens`, `select`, `protectedState` and `readonlyState` were removed. The cost is that Beacon no longer matches the proposal's API, and the glossary keeps "signal" as a lineage term only.
